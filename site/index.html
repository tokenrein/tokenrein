Questions, answered

Does Tokenrein see our prompts?

No. Coding-agent connectors and the SDKs' default mode send only usage (model, tokens, cost, run, user); the agent keeps calling its provider directly. The loop guard keeps a SHA-256 hash of each request, not the request. Proxy mode is optional, and even then nothing is stored.

We already set spend limits with the provider.

A provider limit covers a whole account, after the money is spent, at one provider. Tokenrein acts before each call, per run, per agent, per person and per project, across providers, and a run that hits its limit can wait for a person instead of failing.

What happens if Tokenrein is down?

Agents keep working. Tokenrein fails open by default: the hooks answer "allow" after four seconds and the SDKs carry on. An org can switch to fail-closed if it would rather stop.

Can a paused run carry on?

Yes. An approver adds budget from the Approvals page or the alert, and the run continues from the call it stopped at. Every request and decision is in the audit log.

Which agents and models does it cover?

Claude Code, OpenAI Codex CLI, Gemini CLI and Cursor through connectors, and your own agents through the Python and TypeScript SDKs for OpenAI, Anthropic and any OpenAI-compatible provider: Gemini, Groq, Mistral, DeepSeek, OpenRouter, Ollama.

What does it need to run?

One stateless binary, Redis 7 and Postgres 15 or newer. Docker Compose for one host, a Helm chart for Kubernetes. It runs as non-root on a distroless image, with Prometheus metrics and readiness probes.

Is it open source?

The server is source-available under the Elastic License 2.0: run it and change it in your own infrastructure, but not resell it as a hosted service. The SDKs and connectors are Apache-2.0.

Deploy Tokenrein

cd tokenrein/deploy && cp .env.example .env
echo "TOKENREIN_PUBLIC_URL=https://tokenrein.acme.internal" >> .env
docker compose up -d
docker compose exec tokenrein tokenrein create-owner you@company.com
